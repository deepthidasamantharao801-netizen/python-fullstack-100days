 Introduction to Triggers
A trigger is a special type of stored program that automatically executes (fires) in response to a specific event — INSERT, UPDATE, or DELETE — occurring on a specified table. Unlike a stored procedure, a trigger is never called directly; the database engine invokes it automatically when the triggering event happens.
General Syntax
DELIMITER //
 
CREATE TRIGGER trigger_name
{BEFORE | AFTER} {INSERT | UPDATE | DELETE}
ON table_name
FOR EACH ROW
BEGIN
	-- trigger logic
	-- use NEW.column_name for inserted/updated values
	-- use OLD.column_name for deleted/previous values
END //
 
DELIMITER ;
| Keyword      | Meaning                                                                                       |
| ------------ | --------------------------------------------------------------------------------------------- |
| BEFORE       | Trigger fires before the triggering event is applied to the table. Often used for validation. |
| AFTER        | Trigger fires after the triggering event has been applied. Often used for auditing/logging.   |
| NEW          | Refers to the new row values. Available in INSERT and UPDATE triggers.                        |
| OLD          | Refers to the row values before the change. Available in UPDATE and DELETE triggers.          |
| FOR EACH ROW | Required in MySQL — the trigger body runs once per affected row.                              |

 Database Schema
The examples in this document use the following Employees table and an Employee_Audit table used to log insert, update, and delete activity.
Employees Table:
CREATE TABLE Employees (
	emp_id INT PRIMARY KEY,
	emp_name VARCHAR(50),
	department VARCHAR(30),
	salary DECIMAL(10,2),
	experience INT,
	city VARCHAR(30)
);

	audit_id INT AUTO_INCREMENT PRIMARY KEY,

	old_salary DECIMAL(10,2),

	action_time DATETIME

Trigger Examples
1. BEFORE INSERT (Validation)
Question:
Do not allow employees with salary less than ₹20,000.
Trigger SQL:
DELIMITER //
 
CREATE TRIGGER trg_before_insert_salary
BEFORE INSERT
ON Employees
FOR EACH ROW
BEGIN
	IF NEW.salary < 20000 THEN
    	SIGNAL SQLSTATE '45000'
    	SET MESSAGE_TEXT='Salary cannot be less than 20000';
	END IF;
END//
 
DELIMITER ;
Test:
INSERT INTO Employees
VALUES(106,'Arjun','IT',15000,2,'Delhi');
Output:
ERROR 1644 (45000):
Salary cannot be less than 20000

3. AFTER INSERT (Auditing)
Question:
Store inserted employee details in the audit table.
Trigger SQL:
DELIMITER //
 
CREATE TRIGGER trg_after_insert
AFTER INSERT
ON Employees
FOR EACH ROW
BEGIN
	INSERT INTO Employee_Audit
	(emp_id,action_type,new_salary,action_time)

DROP TRIGGER
Drop a specific trigger:
DROP TRIGGER trg_after_insert;
Drop another trigger:
DROP TRIGGER trg_before_update_salary;
Check existing triggers:
SHOW TRIGGERS;
Show trigger definition:
SHOW CREATE TRIGGER trg_after_insert;

PART 3 — QUICK REFERENCE
10. Stored Procedure vs Trigger — Comparison
| Aspect                  | Stored Procedure                             | Trigger                                               |
| ----------------------- | -------------------------------------------- | ----------------------------------------------------- |
| Invocation              | Explicitly called using `CALL`               | Fires automatically on `INSERT` / `UPDATE` / `DELETE` |
| Parameters              | Accepts `IN`, `OUT`, `INOUT` parameters      | No parameters; uses `NEW` / `OLD`                     |
| Can be called manually? | Yes                                          | No                                                    |
| Return value            | Via `OUT` / `INOUT` parameters or result set | None (cannot return values to caller)                 |
| Typical use             | Reusable business logic, batch operations    | Auditing, validation, enforcing rules automatically   |
| Drop statement          | `DROP PROCEDURE`                             | `DROP TRIGGER`                                        |

11. Command Cheat-Sheet
| Task                | Statement                                                                                           |
| ------------------- | --------------------------------------------------------------------------------------------------- |
| Create a procedure  | `CREATE PROCEDURE name(params) BEGIN ... END;`                                                      |
| Call a procedure    | `CALL name(args);`                                                                                  |
| Delete a procedure  | `DROP PROCEDURE [IF EXISTS] name;`                                                                  |
| View procedure code | `SHOW CREATE PROCEDURE name;`                                                                       |
| List all procedures | `SHOW PROCEDURE STATUS WHERE Db = 'db_name';`                                                       |
| Create a trigger    | `CREATE TRIGGER name {BEFORE\|AFTER} {INSERT\|UPDATE\|DELETE} ON table FOR EACH ROW BEGIN ... END;` |
| Delete a trigger    | `DROP TRIGGER [IF EXISTS] name;`                                                                    |
| List all triggers   | `SHOW TRIGGERS;`                                                                                    |


QUESTION & ANSWER BANK
| Question                                                                                       | Answer                                                                                                                                                                                                                       |
| ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Q1. What is a stored procedure?                                                                | A precompiled, named set of SQL statements stored in the database that can be executed using the `CALL` statement. It can accept parameters and contain variables, conditions, and loops.                                    |
| Q2. What is the default parameter mode if none is specified in `CREATE PROCEDURE`?             | `IN`. If no mode is specified, MySQL treats the parameter as an `IN` parameter.                                                                                                                                              |
| Q3. What is the difference between `IN`, `OUT`, and `INOUT` parameters?                        | **IN:** Passes a value into the procedure. **OUT:** Returns a value from the procedure. **INOUT:** Passes a value in and returns its modified value.                                                                         |
| Q4. Why do we use `DELIMITER //` before creating a procedure or trigger?                       | To prevent internal semicolons from terminating the `CREATE` statement prematurely. The client recognizes `//` as the statement terminator.                                                                                  |
| Q5. How do you call a stored procedure that has an `OUT` parameter?                            | Declare a session variable, pass it to the procedure, and retrieve the result using `SELECT`. Example: `CALL proc(@result); SELECT @result;`                                                                                 |
| Q6. How do you permanently remove a stored procedure?                                          | Use `DROP PROCEDURE [IF EXISTS] procedure_name;`                                                                                                                                                                             |
| Q7. What is a trigger in SQL?                                                                  | A database object that automatically executes in response to an `INSERT`, `UPDATE`, or `DELETE` event on a specified table.                                                                                                  |
| Q8. What is the difference between a `BEFORE` trigger and an `AFTER` trigger?                  | **BEFORE:** Executes before the row operation and can validate or modify incoming values. **AFTER:** Executes after the row operation and is commonly used for auditing and logging.                                         |
| Q9. What do `NEW` and `OLD` refer to in a trigger?                                             | **NEW:** Refers to new row values in `INSERT` and `UPDATE` triggers. **OLD:** Refers to previous row values in `UPDATE` and `DELETE` triggers.                                                                               |
| Q10. Can a trigger call a stored procedure or return a value to the caller?                    | A trigger can call certain stored procedures, subject to MySQL restrictions, but it cannot directly return a value to the statement that fired it.                                                                           |
| Q11. Why use `FOR EACH ROW` in a MySQL trigger?                                                | MySQL supports row-level triggers, so `FOR EACH ROW` is mandatory. The trigger executes once for each affected row.                                                                                                          |
| Q12. How would you reject an invalid `INSERT` using a trigger?                                 | Create a `BEFORE INSERT` trigger with an `IF` condition and use `SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'error message';` to reject the insert.                                                                          |
| Q13. Give a real-world example of using a trigger for auditing.                                | An `AFTER UPDATE` trigger on an employee table inserts the employee ID, old salary, new salary, and timestamp into a salary history table.                                                                                   |
| Q14. Give a real-world example of using a trigger for validation.                              | A `BEFORE INSERT` trigger on a products table rejects rows where quantity is negative or price is less than or equal to zero.                                                                                                |
| Q15. How do you remove a trigger from a database?                                              | Use `DROP TRIGGER [IF EXISTS] trigger_name;`. It removes the trigger definition, not the table or its data.                                                                                                                  |
| Q16. What is the main advantage of stored procedures over sending raw SQL from an application? | They support reusable business logic, reduce network traffic, centralize database operations, and allow access control through `EXECUTE` privileges. Performance benefits depend on the workload and database configuration. |
| Q17. Can a single table have multiple triggers for the same event?                             | Yes. MySQL supports multiple triggers for the same event and timing from version 5.7.2 onward. Their execution order can be controlled using `FOLLOWS` or `PRECEDES`.                                                        |
| Q18. What happens to existing data in a table when its trigger is dropped?                     | Nothing. `DROP TRIGGER` removes the trigger definition but leaves existing table data unchanged.                                                                                                                             |
